# 术语扫盲表（Day 1 自测用）

> 自测方法：遮住右边解释，能说出 80% 的词即过关。说不上的打星号，Day 1 结束前重看。

## 一、大模型基础

| 词 | 一句话解释 |
|---|---|
| LLM（大语言模型） | 用海量文本训练出来的大模型，如 GPT、DeepSeek、Kimi |
| Prompt（提示词） | 你发给模型的指令和上下文，模型基于它生成回复 |
| Token | 模型处理文本的最小单位（约 0.5~1 个汉字），**按 token 计费、限制长度** |
| 上下文窗口 | 模型一次能"看到"的最大 token 数，如 32K、128K |
| Temperature（温度） | 控制随机性：0 输出稳定确定，1 输出发散多变 |
| 幻觉（Hallucination） | 模型一本正经地编造事实——RAG 和护栏就是为了压它 |
| 流式输出（Streaming） | 边生成边返回，打字机效果 |
| 多模态 | 模型同时处理文本/图片/音频等多种输入 |
| API 调用 | 通过 HTTP 接口调服务商的模型（本项目方式），对应概念是"本地部署开源模型" |

## 二、模型怎么来的（面试会考浅层概念）

| 词 | 一句话解释 |
|---|---|
| 预训练（Pretrain） | 用海量文本无监督学习，得到"基座模型" |
| 微调（Fine-tuning） | 用特定领域数据继续训练，改变模型的行为/风格/知识 |
| LoRA | 低成本微调：只训练一小部分附加参数，省钱省卡 |
| RLHF | 人类反馈强化学习，让输出更符合人类偏好 |
| 量化（Quantization） | 降低权重精度省显存，如 FP16→INT8，效果略降 |
| 推理（Inference） | 模型生成回答的过程（"训练"的反义词） |

## 三、RAG 全家桶

| 词 | 一句话解释 |
|---|---|
| RAG（检索增强生成） | 先检索资料、再让模型基于资料回答：治幻觉、补新知识 |
| Embedding（向量嵌入） | 把文本变成一串数字向量，语义越近向量距离越近 |
| 向量数据库 | 专门存向量、做相似度检索的库：Milvus / FAISS / Chroma |
| 语义检索 | 按向量距离找"语义相关"的片段 |
| BM25 | 经典关键词检索算法，精确匹配强、不理解语义 |
| 混合检索 | BM25 + 向量检索一起用，取长补短 |
| 切分（Chunking） | 把长文档切成小段——**切多大直接决定检索质量** |
| Top-K | 检索时返回最相似的 K 个片段 |
| Rerank（重排序） | 用更精细的模型对初步检索结果重新打分排序 |
| Metadata Filter | 按来源/时间/类别等字段先过滤、再检索 |
| 查询改写 | 把用户原始问题改写成更适合检索的形式（拆题、扩展、翻译） |
| GraphRAG | 结合知识图谱的 RAG，擅长"多跳/关系型"问题 |
| Agentic RAG | 让 Agent 自己决定"怎么检、检几轮、何时停"的 RAG |
| RAGAS | 常用 RAG 自动评估框架；核心指标如忠实度、答案相关性 |
| 忠实度（Faithfulness） | 回答内容是否真的来自检索到的资料（防幻觉的核心指标） |

## 四、Agent 核心

| 词 | 一句话解释 |
|---|---|
| Agent（智能体） | 能自主循环"思考→行动→观察→再思考"来完成任务的系统，不是单次问答 |
| Agent Loop | 感知→规划→行动→观察 的循环，Agent 的心脏 |
| Tool Calling / Function Calling | 让模型输出结构化请求去调外部工具（查天气、算数、查库）；**两者基本是同一个东西** |
| ReAct | Reasoning + Acting：边推理边行动，最流行的 Agent 范式 |
| CoT（思维链） | 让模型"一步步思考"，提升推理准确率 |
| Planning（规划） | 把大任务拆成小步骤，复杂任务先出计划再执行 |
| Planner / Executor | 负责想步骤的角色 / 负责执行的角色 |
| Memory（记忆） | 短期记忆 = 当前会话上下文；长期记忆 = 存数据库、可跨会话回忆 |
| Reflection（反思） | 让模型检查并改进自己的输出 |
| Multi-Agent（多智能体） | 多个分工的 Agent 协作，如研究员 + 写手 + 审核 |
| Supervisor（主管模式） | 一个调度 Agent 负责把任务分派给其他 Agent |
| Guardrails（护栏） | 防越界/防有害输出的机制：输入过滤、输出校验、兜底回复 |
| Human-in-the-loop | 关键节点暂停、等人工确认后再继续 |
| MCP（Model Context Protocol） | Anthropic 提出的开放协议：让模型用统一方式接外部工具/数据源，相当于"工具接口标准化" |

## 五、框架与工具

| 词 | 一句话解释 |
|---|---|
| LangChain | 最流行的 LLM 应用编排框架，模块全、灵活 |
| LlamaIndex | 专注数据接入与 RAG 的框架 |
| LangGraph | LangChain 家的图/状态机框架，用节点+边编排复杂 Agent 流程——**本计划主力** |
| Dify / Coze | 低代码搭建 Agent/RAG 应用的平台（面试要知道，开发岗更重代码） |
| LangSmith / Langfuse | LLM 应用观测平台：记录每一次调用（trace），用于调试和评测 |

## 六、易混淆辨析（面试高频）

- **RAG vs 微调 vs 长上下文**：补新知识首选 RAG；改行为/风格才微调；长上下文塞全文省事但有噪声、贵、长度有限。
- **Function Calling vs MCP**：FC 是模型的能力（工具定义写在你的代码里）；MCP 是协议（工具以标准服务的形式提供，模型可自动发现）。MCP 可以理解为"FC 的工具清单外置 + 标准化"。
- **LangChain vs LangGraph**：LC 是链条式编排，适合线性流程；LG 是图/状态机，适合有循环、有分支的 Agent——面试答得出这一句就够。
