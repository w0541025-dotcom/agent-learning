## Q1: LangChain 做了什么？/ 你为什么用（或不用）LangChain？

**① 一句话定位**
LangChain 是 LLM 应用开发框架，把"调模型、接数据、编排流程"这些重复劳动封装成现成组件，不用从零造轮子。

**② 分层展开**（它封装了三层）
- Model I/O：prompt 模板、统一模型接口（换 OpenAI/DeepSeek/Kimi 只改三行）、输出解析
- Retrieval：文档加载器、切分器、embedding 接口、几十种向量库的对接
- 编排：Chain（线性流程）→ LangGraph（图/状态机，做多分支、有循环的 Agent 流程）

**③ 我的实践**
学习时我先不用框架，用 numpy + sentence-transformers + openai SDK 手写了最小 RAG
（加载→切分→embedding→相似度检索→拼 prompt→调 API，约 100 行，见 projects/rag-project/minimal_rag.py）。
后来对比 LangChain 版教材代码，流程一一对应——它本质是把四个环节抽象成
Loader / Splitter / Embeddings / VectorStore 接口。
**框架提供的是工程抽象和生态对接，不是新能力；检索内核还是 embedding + 余弦相似度。**

**④ 一句权衡**
LangChain 生态大、对接全，但抽象层厚、版本迭代快、报错栈深难调试；
也有团队生产环境直接用 openai SDK + 自研轻量管线。选型看团队规模和需求复杂度。

**必背对比句**：LangChain 通用编排 / LlamaIndex 专注 RAG 数据侧 / LangGraph 图状态机做复杂 Agent。
